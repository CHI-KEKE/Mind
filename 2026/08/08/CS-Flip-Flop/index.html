Flip-Flop - 讓電路記住一件事情

Created2026-08-08|Updated2026-08-10|CS
|Post Views:
▸Logic Gate 只認得「現在」

在網路上搜尋邏輯閘，可以找到 AND、OR、NOT、NOR、XOR 這些能「計算」的元件，舉例來說：

combinational-logic.sim 
A = 1
B = 0

A AND B = 0

它們的共同特性是：現在輸入是多少，輸出就由它決定，把輸入改掉，輸出就跟著改掉，完全沒有「之前發生過什麼」的概念。

▸問題：算完的結果要留在哪裡

若要做計算機，就會遇到 3 + 5 = 8 這種情況，算出 8 之後，下一步可能還要 8 + 7，因此我們需要某種東西，能讓算出的 8 被留著。

💡 問題就變成：怎麼讓電路具有記憶？
▸普通電路：一路往前
straight-through.circuit 
輸入
 ↓
Gate
 ↓
輸出
▸把輸出接回輸入

如果我們把輸出接回自己的輸入呢？就變成：

feedback.circuit 
        ┌──────────┐
        ↓          │
輸入 → Gate → 輸出 ┘

這叫 Feedback（回授），這個想法很重要，因為現在上一刻的輸出變成下一刻的輸入，也就是過去的狀態開始有能力影響現在，而這便是記憶出現的基礎。

▸兩顆 NOR 的接法

我們先拿兩顆 NOR。每顆 NOR 都有兩個輸入、一個輸出，我們這樣定義：

NOR 1 輸入：S、Q̅NOR 1 輸出：Q
NOR 2 輸入：R、QNOR 2 輸出：Q̅
▸互相餵對方：Cross-coupled
cross-coupled.circuit 
        ┌────────────────┐
        ↓                │
S → NOR 1 → Q → NOR 2 ← R
    ↑              │
    └──── Q̅ ←─────┘

這就是 Cross-coupled NOR gates，兩顆 NOR 互相交叉回授。這組電路有個正式名字，叫 SR Latch（S = Set、R = Reset）。

▸穩定狀態下的循環

假設目前：

Q = 0Q̅ = 1

然後我們讓：

S = 0R = 0

看看會發生什麼。

nor-1.eval 
S  = 0
Q̅ = 1

NOR(0,1) = 0  →  Q = 0
nor-2.eval 
R = 0
Q = 0

NOR(0,0) = 1  →  Q̅ = 1

結果 Q = 0、Q̅ = 1，完全沒有變。而且它會一直這樣循環下去：

steady-state.loop 
Q=0 → 讓 Q̅=1 → 又讓 Q=0 → ...（穩定狀態）
▸寫入一次，看它是否記住

接著我們實際做一次「寫入」，假設：

S = 1R = 0
write.eval 
NOR 1：NOR(1, ?) = 0  →  Q = 0
NOR 2：NOR(0, 0) = 1  →  Q̅ = 1

我們可以把這一步理解成：把 Q 設成 0。

真正的「記住」發生在下一步。 現在把剛才的 S = 1 撤掉，變成：

S = 0R = 0

注意，現在已經沒有外部輸入在說「Q 給我等於 0！」，可是 Q 依然是 0。為什麼？因為：

retain.loop 
Q=0 → 使 Q̅=1 → Q̅=1 → 又使 Q=0 → 循環

寫入時： S=1 R=0  →  Q=0
放開後： S=0 R=0  →  Q=0
過一段時間後： S=0 R=0  →  Q=0

這個「外面的寫入訊號消失了，Q 卻還維持著」，就是記憶。假設我只告訴你 S = 0、R = 0，然後問「Q 是多少？」這其實答不出來，它可能是 0，也可能是 1，因為要知道的是它之前被設定成什麼。

元件 輸出取決於
普通 Logic Gate 現在輸入
Latch 現在輸入 + 之前狀態
這就是「記憶」的本質。
▸需要能寫、也需要能保持

而且這正是我們希望它具有的能力。如果記憶體寫入一次之後永遠不能修改，那也沒什麼用。所以我們需要兩種能力：

① 我想寫入時 → 可以改變 Q② 我不想寫入時 → Q 自己維持

SR Latch 的 S、R 就是控制它的外部輸入。在 Hold 狀態下，你必須確保 S、R 都維持在正確的非作用狀態。

▸S／R 一旦亂變，資料就跟著亂變

對這個 NOR SR Latch 來說：

S = 0R = 0

代表「不要改資料」。如果外部突然變成：

R = 1

那就是在要求 Latch 改變狀態。所以其實已經發現 SR Latch 的一個工程問題：既然 S／R 可以直接影響記憶，就必須非常小心控制它們，避免不小心觸發寫入。

這個問題會直接帶我們走向後面的 D Latch 和 Flip-Flop。
▸只准在指定的那一刻寫入

既然 Latch 已經能記，為什麼還需要 Flip-Flop？因為剛才已經發現問題「我要如何確保 S／R 不會亂變？」

我們真正希望的是外面的資料可以一直變（0 → 1 → 0 → 1 → 0 → 1），但記憶元件不要一直跟著亂變。我們希望能說「現在才准你存！」。例如資料 D 是

data.waveform 
D:  0 ── 1 ── 0 ── 1 ── 1
                        ↑
                     就這一刻，我只想記住這瞬間的 1

所以我們需要另外一個控制訊號，這就是 Clock。以最常見的 D Flip-Flop 來看：

d-flip-flop.block 
         ┌───────────────┐
D   ────→│               │
         │ D Flip-Flop   ├────→ Q
CLK ────→│               │
         └───────────────┘

你只需要關心：D = 想存什麼、CLK = 什麼時候存、Q = 現在存著什麼。例如目前 Q = 0，外面的 D 可以一直變（0 → 1 → 0 → 1 → 1），Q 不需要每次都跟著變，直到 Clock 的指定邊緣：

clock.waveform 
CLK: ________|‾‾‾‾
              ↑
            就現在，假設這一刻 D = 1，Flip-Flop 就捕捉 Q = 1，然後繼續保持
可以把它想成：Clock 在某個瞬間喊「拍照！」，Flip-Flop 把當下 D 的值拍下來，然後維持這個值。
▸一層一層疊上去的抽象

完整 Flip-Flop 需要更多電路來控制，是一層一層疊上去的：

Gate基本 Logic Gates
↓ 加入 Feedback
LatchCross-coupled NOR
↓ 加入資料與時間控制
Flip-FlopD + CLK → Q

例如一個 D Flip-Flop 的內部實作，可以由多個 Gate／Latch 組成，但對 CPU 設計者來說，可以把它抽象成：

ff.abstract 
         ┌──────┐
D   ────→│  FF  │────→ Q
CLK ────→│      │
         └──────┘

只需要知道：一個 FF 可以保存 1 bit，並且在指定 Clock edge 更新。

▸很多 Flip-Flop 組成 Register

假設 CPU 想保存 0101，可以使用四個 Flip-Flop：

register.block 
D3 ──→ [FF] ──→ Q3 = 0
D2 ──→ [FF] ──→ Q2 = 1
D1 ──→ [FF] ──→ Q1 = 0
D0 ──→ [FF] ──→ Q0 = 1
         ↑
         │
       Clock

四個一起就是 0 1 0 1，也就是十進位的 5。這組東西就是 Register（暫存器）

Flip-Flop 數量 可保存位元
1 個 1 bit
8 個 8 bits
64 個 64 bits
很多個組合 Register（暫存器）
