RAM and Pointer

Created2026-08-15|Updated2026-08-16|CS
|Post Views:

今天打開一個遊戲，這個很日常的動作背後，其實就是 RAM（記憶體）開始忙碌的過程。用五個步驟拆開來看

🎮🌿🌼🐻
情境導覽
從打開一個遊戲，認識 RAM 的角色
遊戲原本安靜地待在 SSD 裡，直到啟動之後，RAM 才開始忙碌起來。
01
遊戲原本存在 SSD程式、圖片、音效、地圖資料都安靜地存放在硬碟裡，還沒被使用
02
啟動遊戲作業系統把目前需要的程式與資料，從 SSD 載入 RAM
03
CPU 從記憶體取得資料CPU 讀取 RAM 裡的內容，才能真正執行遊戲
04
開越多程式，RAM 用越多每個程式都要佔用一部分 RAM 空間，同時開的程式越多，剩餘空間越少
05
關機後，RAM 內容通常會消失RAM 屬於揮發性記憶體，需要持續供電才能維持資料

按下「儲存」之後，資料才會真正寫入 SSD 等持久儲存裝置，這也是為什麼「存檔」這個動作這麼重要。

RAM 的本質可以想成幾十億個極小的電子狀態儲存格，硬體把這些儲存格組織起來，再讓 CPU 用地址找到某一段資料。

RAM 的兩種樣貌：抽象模型與物理實體

抽象模型
寫程式時最好用的想像，一排連續編號的格子，每格都有自己的地址
🔩
物理實體
實際硬體是 PCB 電路板搭配 DRAM 晶片，裡面才是真正的記憶體 Cell

CPU 給出地址之後，硬體才會去找對應的資料，用高度簡化的流程來看：

01
CPU 提出要求我要 Address 0x1000 的資料

03
DRAM 回傳資料取得 01000001 之後送回給 CPU

所以程式裡看到 int x = 10;，底層牽涉到的概念就是某段記憶體位置儲存了 x 的資料，內容是 00000000 00000000 00000000 00001010。假設 int 是 4 bytes，它通常會佔用連續的數個 byte 位址。

ref 可以當成 Pointer 某種用途的高階語言版本，但 Pointer 本身還能拿來建立資料結構、走訪陣列、操作動態記憶體、與硬體或 OS API 溝通。

如果直接記成「C Pointer 等於 C# ref」，之後會遇到問題，因為 C 的 pointer 用途廣得多。舉例來說，pointer 可以先宣告成普通變數再指定指向誰：

甚至還有 int **pp = &p; 這種指標的指標，也就是 Pointer to Pointer。

C Pointer 能做到、但 C# ref 做不到的事
  • 修改外部變數（這部分跟 ref 很像）
  • 指向其他資料，之後可以隨時改指向別的目標
  • 進行 Pointer 運算，例如走訪陣列位址
  • 操作動態記憶體，配合 malloc／free
  • 建立 Linked List、Tree 等需要「自我指向」的資料結構
  • 用於系統程式設計，直接與硬體或 OS API 溝通

一句話總結，Pointer 讓程式把「記憶體位置」本身當成一個值來保存、傳遞，並透過它存取那個位置上的資料。Pointer 最強的地方，就是「資料在哪裡」這件事情，也能變成程式可以保存和操作的資訊。
