Ring Buffer

Created2026-09-10|Updated2026-09-13|CS
|Post Views:
DATA STRUCTURE NOTE

資料會一直增加，空間卻不會變大

只要資料會持續流入，就要先決定容量上限，以及空間用完之後要保留什麼、捨棄什麼。Ring Buffer 用固定大小的記憶體循環使用。

固定容量

資料不會讓記憶體無限成長。

循環索引

走到最後一格後回到索引 0。

滿載策略

空間用完後要定義資料保留規則。

CORE IDEA

一排格子，繞一圈繼續使用

Ring Buffer 是固定數量的格子。資料寫到最後一格後回到第一格。

  1. 配置容量為 5 的陣列：[, , , , _]。
  2. writeIndex 指向下一筆資料要寫入的位置。
  3. 使用 (index + 1) % capacity 計算下一個索引。 
buffer = [_, _, _, _, _]
          0  1  2  3  4

寫入 A：
[A] [_] [_] [_] [_]
     ↑
   write
關鍵觀念：「Ring」描述的是索引如何循環，記憶體本身仍然是一段連續的陣列。

為什麼不需要搬動資料

只要把 readIndex 往前移，就能表示資料已經被讀取，原本的值不必立刻搬走。

READING WINDOW

資料沒有搬家，閱讀起點改變了

目前的 readIndex 決定邏輯上的第一筆資料。 

index
  0  1  2  3  4
[F][G][C][D][E]
       ↑
      read

readIndex = 2
讀取順序：C → D → E → F → G

實際記憶體

陣列位置依然是 0 到 4。

邏輯順序

從 readIndex 開始循環讀取。

操作成本

讀寫主要是更新索引。

INDEX WRAPAROUND

% 把索引帶回循環範圍

取餘數只是把「走到底後回到起點」寫成索引計算。 

index = (index + 1) % size;

index++;
if (index == size)
{
    index = 0;
}

SYSTEM VIEW

Ring Buffer 是兩種速度之間的暫存區

它可以吸收短時間的速度差，但不能消除長期的產能落差。

Producer → Ring Buffer → Consumer

Producer
持續產生資料
↓
Ring Buffer
固定容量暫存區
↓
Consumer
逐筆處理資料

閱讀方式：紅色代表資料入口，藍色代表緩衝核心，綠色代表資料處理端。箭頭表示資料流向。

網路封包

封包持續進入，處理程式逐筆取出。

音訊與 UART

短時間的處理延遲可以先放在緩衝區。

Sensor

固定容量能控制記憶體使用量。

C# IMPLEMENTATION

完整的 Ring Buffer 實作

這個版本保留原本的 Main()、泛型類別、讀寫索引與輸出紀錄，完整展示資料如何進入與離開環形緩衝區。

展開完整 C# 程式碼
  1. Write 使用 writeIndex 寫入資料，再以 % Capacity 移動到下一格。
  2. Read 使用 readIndex 取出資料，再把已讀位置清成預設值。
  3. 原始版本保留了完整執行流程，空與滿的安全檢查可在後續版本另外補上。
WHEN THE BUFFER IS FULL

容量只能延後問題，不能消除速度差

假設 Producer 每秒產生 100 筆，Consumer 每秒只能處理 50 筆，緩衝區最終仍然會滿。 

Producer：每秒產生 100 筆
        ↓
Ring Buffer：容量有限
        ↓
Consumer：每秒處理 50 筆

覆蓋舊資料

保留最新資料，捨棄較早資料。

丟掉新資料

保留緩衝區內的資料，新進資料寫入失敗。

等待處理端

讓寫入端暫停或降低速度。

另一種選擇：把壓力轉移到 Disk、Queue 或 Broker，也要另外定義容量、失敗與恢復策略。

設計時需要先回答的問題

  • 資料過期後是否還有價值？
  • 滿載時能不能遺失最新資料？
  • 寫入端能不能暫停或降速？
  • 資料是否需要跨程序或跨機器保存？
結論：Ring Buffer 解決固定空間內的循環讀寫，以及短時間的速度差。長期速度落差仍需要資料保留、背壓或外部佇列策略。
